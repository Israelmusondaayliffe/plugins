# Shared prompting contract

Deliver copyable prompts by default on every host, including Claude Code, Claude Cowork, and Codex. Generate images only when the user asks or an approved bounded test covers the operation. An explicit Midjourney operation can act through the host's available browser surface (an in-app browser, a browser extension bound to the user's existing session, or Computer Use) where it permits the needed browser actions. Do not fabricate a tool call, selected model, rendered image or creative acceptance.

Follow the user's model and output count. When no model is named, write a broadly compatible non-Midjourney prompt. No model questionnaire is needed. Distinguish number of prompt alternatives, number of images requested inside a prompt, and panels inside a composite. For a singular request deliver one complete prompt; for open exploration choose a useful small set. No seven/ten/twelve quota, mandatory diversity distribution or word cap.

Read the supplied images before describing them. Name references by visible content and role; numbered attachment labels are useful when matched to the host. Keep explicit reference priority and the user's chosen changes. For a new shot, natural changes in pose, gaze, emotion and light can follow the camera; for a controlled study, keep continuity while representing the new view physically. Do not force reposing into a faithful medium conversion.

Use the requested format. Otherwise choose natural language for a flowing creative brief, JSON for addressable constraints or preservation, and a system-style operating prompt for a shared image set or reusable prompt-making role. These are alternative useful writing formats, not a universal ranking. JSON and XML prompt text do not create API controls or higher message authority. The same craft can serve compatible models. Read [format-ladder.md](format-ladder.md) when choosing a format, then only the needed template.

PLAN / SEARCH / GENERATE / VERIFY and the axis preamble remain optional useful formats. Keep the purpose, reference roles, scene and meaningful checks even when labels would clutter the prompt. Browse when facts require it; a SEARCH phrase alone is not evidence of retrieval. Supply verified facts when the generation surface cannot search. Review rendered results only when available.

Use exact supplied copy, names and factual content. Do not fill missing facts with plausible invented details. Clearly distinguish proposed creative copy from approved copy. Tie material, light, camera, texture and graphic terms to observable effects. Apply skin or photographic realism vocabulary only to subjects and media that call for it.

Every delivered prompt belongs in its own triple-backtick block. JSON prompts must parse as JSON after placeholders are filled. Preserve detailed templates where their structure helps; remove redundant or contradictory instructions, not useful creative specificity. Avoid blanket negative inventories. Name the few unwanted changes relevant to this brief.

Brand names in image briefs do not activate or require Brand Studio. Work from supplied references and verified brand material as needed. A user-selected palette library (for example a Wada combination set) is an optional color resource alongside free exploration; see [color.md](color.md) when selected. Other plugins are never dependencies of these skills.

Only save a recipe as a reusable preferred result after the user explicitly selects it. Operational records can track submissions and avoid duplicates without claiming creative approval. User selection is final QA; assistant review can report defects and differences.

During execution, verify the actual selected model, reference attachments and exposed controls. Use existing subscriptions/included credits within the authorized budget. Do not use a paid API, purchase credits or silently change models. Stop on uncertain submission status rather than submitting a duplicate. Model guidance is dated and updated on user request, not through an automatic updater.
