# Workshop Workbench

Build what the facilitator actually needs, from what the source can support.

## Required references

Follow [source and tool policy](../../references/source-and-tool-policy.md) when
current claims or links appear in teaching material. Follow
[evidence and artifact policy](../../references/evidence-and-artifact-policy.md)
to separate source content, facilitator decisions, proposals, and gaps. Read
[advanced execution](../../references/advanced-execution.md) before requesting
an independent package review.

## Inspect before building

Read the supplied material first. Identify the audience, intended change,
workshop length, delivery setting, source authority, existing assets, and
missing decisions. Classify each missing decision as critical or non-critical.
Do not assume the user needs the maximum package.

Recommend a right-sized deliverable set based on the current stage. Possible
components include:

- outcome and audience brief
- timed facilitator run of show
- facilitator guidance and contingencies
- participant guide
- exercises and worked demonstrations
- logistics and materials checklist
- source notes and fact-check record
- feedback and evaluation
- slide outline

Explain why each recommended component is worth producing. Ask the user to
select or correct the set before generating a large package. A direct request
for named deliverables counts as the selection.

## Build

Create the selected materials as a coherent run-ready package. Align outcomes,
agenda, exercises, examples, timing, and evaluation. Keep participant material
separate from facilitator-only guidance. Do not invent case-study results,
testimonials, or source claims.

Do not label the package run-ready while a critical decision is unresolved.
Audience, intended change, duration, delivery setting, facilitator ownership,
and required approvals are critical unless the context clearly makes one
irrelevant. When a blocker remains, create a draft package, name the blocker,
its owner, and the point by which it must be resolved.

For a substantial package, a fresh reviewer may check timing, instructions,
participant clarity, source boundaries, and deliverable completeness. The
primary context repairs and integrates the review.

Use [the Workshop Package template](assets/workshop-package-template.md) as the
package manifest. Finished visual slides require an explicit request and an
appropriate presentation tool.
