# Signal Scout

Find what is changing, recurring, or newly possible now.

## Required references

Read [source and tool policy](../../references/source-and-tool-policy.md) before
searching and follow
[evidence and artifact policy](../../references/evidence-and-artifact-policy.md)
for source labels and citations. Read
[advanced execution](../../references/advanced-execution.md) before using
parallel agents.

## Scope the scan

Establish the audience, question, geography if relevant, time window, and
decision the scan should inform. Infer these from the request when safe. Ask
only when materially different interpretations would change the search.

## Search

1. Create distinct search lanes such as official change, practitioner
   experience, repeated pain, alternatives, and counter-signal.
2. Use current web search. Open the underlying pages and record dates when
   recency matters.
3. Prefer primary owners for facts. Use forums, reviews, Reddit, social posts,
   and community discussions for experience and language.
4. Search for disconfirming evidence and signs that a loud signal is not
   representative.
5. Stop when additional searches repeat known patterns or cannot affect the
   decision.
6. Keep a compact search log with the query or source lane, access result, and
   limitation. Record blocked, unavailable, or inaccessible sources rather
   than silently omitting them.

For a broad scan with genuinely independent lanes, use two to four bounded
workers when the host supports them. A single-agent sequential run must remain
fully supported.

## Synthesize

Cluster evidence into named signals. For each signal show:

- what is happening
- who appears affected
- strength and freshness of evidence
- representative links
- counter-evidence or bias
- why it might matter
- a safe next check

Rank signals only against the user's stated purpose. Do not turn frequency in
search results into a population claim.

Classify the scan outcome as `current scan`, `partial scan`, `unavailable`, or
`no qualifying signal`. Do not manufacture a signal to fill the template. A
partial or unavailable result must name what was attempted, what failed, and
which claims cannot be made. A no-signal result must distinguish genuinely
weak evidence from insufficient coverage.

## Artifact

Use [the Signal Scout template](assets/signal-scout-template.md). This is a
dated snapshot, not a monitoring dashboard. A later run may compare against a
saved snapshot, but never imply activity between runs.
