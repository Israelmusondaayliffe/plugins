# Creative Project Control Room

Keep creative intent and production reality in the same record.

## Shared rules

Use [source and tool policy](../../references/source-and-tool-policy.md) when
checking current references or rendered assets. Follow
[evidence and artifact policy](../../references/evidence-and-artifact-policy.md)
for source status and external writes.

## Establish the control pack

1. Record the brief as proposed, draft, or approved. State the audience,
   intended response, creative proposition, deliverables, channels,
   constraints, deadline, and approval authority. Do not call it approved
   without an approval source and date.
2. Register source references with provenance, usage rights if known, intended
   influence, and forbidden copying or drift.
3. Inventory every required asset. Record format, owner, source, dependencies,
   status, version, review evidence, and delivery location.
4. Record creative and production decisions separately from open questions.
   Every approved decision needs an owner, date, and approval evidence.
5. Map responsibilities, approval gates, risks, blockers, and recovery paths.
6. Define what counts as approved, delivered, and archived.

Browser may verify a rendered reference or asset when the page state matters.
Computer use or a connected write requires an explicit request. Mark licensing
or provenance unknowns instead of assuming permission.

## Operate

Update the control pack from supplied production evidence. Never mark an asset
complete solely because someone said it was started. Preserve superseded
decisions when they explain downstream work. Highlight conflicts between the
approved brief and current assets.

Use [the Creative Control Pack template](assets/creative-control-pack-template.md)
and the optional [asset register CSV](assets/asset-register.csv). Generate or
edit creative assets only when the user explicitly asks and the suitable
specialist capability is available.
