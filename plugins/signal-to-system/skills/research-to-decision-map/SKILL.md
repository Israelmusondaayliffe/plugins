# Research To Decision Map

Make the decision logic visible before turning evidence into commitment.

## Required references

Follow [source and tool policy](../../references/source-and-tool-policy.md) for
targeted gap checks and
[evidence and artifact policy](../../references/evidence-and-artifact-policy.md)
for claim status. Read
[advanced execution](../../references/advanced-execution.md) before using an
independent evidence or critic lane.

## Pass one: provisional map

1. State the decision, options, decision owner, constraints, and required
   decision horizon.
2. Inventory the supplied research. Separate verified facts, supplied claims,
   assumptions, judgment, and missing evidence.
3. Map each option against the decision criteria. Preserve disagreements and
   explain which source or value produces each difference.
4. Search only to verify unstable claims or close a material gap that could
   change the result. Do not restart the whole research process by default.
5. Identify the strongest evidence for and against each viable option.
6. Judge whether the evidence is sufficient for the decision's consequence and
   reversibility. Choose one honest status:
   - `recommend` when the material claims and criteria are adequately supported
   - `recommend provisionally` when a reversible choice can proceed with named
     uncertainty and a review trigger
   - `decline pending evidence` when a material gap could change the choice
7. When justified, give a recommendation with confidence, key risks, strongest
   alternative, and the evidence that would change it. When declining, name
   the smallest evidence needed before reconsideration.

For a consequential or disputed decision, an independent critic may test the
evidence map. Integrate the critique rather than appending it as a separate
answer.

## Decision gate

Present the provisional map and ask the user to choose, correct a value, or
delegate the final choice. Do not record a final user decision before this
gate. If the user explicitly delegated the decision in the original request,
state that authority and proceed.

## Pass two: final record

Record the selected option, decision rationale, confidence, accepted risks,
rejected alternatives, unresolved evidence, review trigger, and immediate next
action. Preserve a different user choice without rewriting the evidence to
make it appear inevitable.

Use [the Research-to-Decision template](assets/research-to-decision-template.md).
The work ends at a decision record. Further execution needs its own authority.

Use Capability Matcher and Brief Builder when the central job is selecting a
person, agent, tool, product, or service. Use Experiment Designer and Ledger
when the missing work is an evidence-grade test rather than a decision record.
