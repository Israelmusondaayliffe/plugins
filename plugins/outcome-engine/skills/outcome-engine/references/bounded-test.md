# Bounded test branch

Use a bounded test when an important, uncertain assumption should be tested before committing to a full plan or implementation.

Define the decision, single riskiest assumption, cheapest reversible test, time and authority boundary, evidence surface, pass/fail/inconclusive rules, stop condition, and follow-on decision owner.

Execute only the test through `evidence-driven-delivery`. Do not quietly turn a prototype into production. At the stop condition, report the evidence and recommend proceed, revise, abandon, or run a separately approved follow-up test.
